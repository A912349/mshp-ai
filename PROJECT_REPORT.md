# Краткое описание проекта для сдачи

## Тема

Упаковка модели MediaPipe в готовое приложение: распознавание жестов руки в реальном времени с клиентской камерой.

## Актуальность

Компьютерное зрение активно используется в интерактивных приложениях: фитнес-тренерах, образовательных играх, системах управления жестами и сервисах анализа движений. Готовые модели MediaPipe позволяют быстро получить координаты ключевых точек руки и использовать их в пользовательском интерфейсе без самостоятельного обучения модели.

## Цель

Создать работающее веб-приложение, которое получает видеопоток с камеры пользователя в браузере, передаёт кадры в модель MediaPipe на backend, визуализирует ключевые точки руки и реагирует на предсказания модели через определение простых жестов.

## Задачи

1. Изучить формат данных MediaPipe Hand Landmarker.
2. Реализовать получение видеопотока с камеры клиента через браузерный API `getUserMedia()`.
3. Передавать кадры с клиента на Flask backend.
4. Подключить модель MediaPipe Hand Landmarker к backend-обработке кадров.
5. Реализовать визуализацию ключевых точек и связей руки.
6. Добавить прикладную логику: подсчёт поднятых пальцев и определение жестов.
7. Создать интерфейс с помощью Flask, HTML, CSS и JavaScript.
8. Подготовить инструкцию по запуску и демонстрации.

## Используемые технологии

- Python
- Flask
- OpenCV
- MediaPipe Tasks API
- NumPy
- Pillow
- HTML/CSS/JavaScript
- Browser MediaDevices API

## Архитектура решения

В проекте не используется `cv2.VideoCapture(0)` на backend, потому что такой подход берёт камеру сервера. Вместо этого камера открывается на стороне клиента в браузере. JavaScript получает кадры с видеопотока, отправляет их на endpoint `/process_frame`, Flask обрабатывает изображение через MediaPipe и возвращает обработанный кадр с результатами распознавания.

## Результат

Создано веб-приложение, которое показывает изображение с камеры клиента, рисует скелет руки, считает количество поднятых пальцев и отображает название распознанного жеста. Приложение можно запустить локально и использовать для живой демонстрации.

## Вывод

Проект показывает, как готовую ML-модель можно превратить в удобное веб-приложение. Основная ценность заключается не только в запуске модели, но и в правильной архитектуре: камера работает на стороне клиента, обработка выполняется на backend, а результат возвращается в интерфейс пользователя.


## Улучшения интерфейса и доступа к камере

В обновлённой версии исправлена некорректная диагностика доступа к камере. Раньше при открытии проекта через небезопасный адрес браузер мог показывать сообщение, что камера не поддерживается. Теперь приложение отдельно проверяет безопасный контекст и объясняет пользователю, что страницу нужно открывать через `localhost`, `127.0.0.1` или HTTPS. Также добавлены запасные настройки качества камеры и более спокойный пользовательский интерфейс без лишнего “нейросетевого” оформления.

## Дополнительные функции демонстрационной версии

В расширенной версии проекта добавлены элементы, которые делают приложение удобнее для показа пользователю: история распознанных жестов, сохранение снимка обработанного кадра, переключение качества обработки, сетка кадра, полноэкранный режим, тёмная тема и смена камеры на устройствах с несколькими объективами. Также добавлены таймер сессии, счётчик обработанных кадров и отображение разрешения камеры. Эти улучшения не меняют основную логику модели, но повышают удобство интерфейса и делают проект более завершённым как веб-приложение.
